## 1. Atom-фіди

Три фіди, як домовились: `/feed.xml`, `/feed/<серія>.xml`,
`/feed/vendor/<slug>.xml`. **382 вендорські фіди**, генерація копійчана.

Усі чотири ваші застереження закриті:

| Ризик | Що зроблено |
|---|---|
| `id` не вічний | `tag:allservices.one,2026:change/<run_id>` — на подію, не на URL модуля |
| `updated` = час генерації | `updated` = час **прогону**; у самого фіда — час найсвіжішої події |
| Перша генерація вивалює тисячі | сівба, див. нижче — і вона виявилась хитрішою, ніж у вашому описі |
| Розмір і self-link | ліміт 200, `<link rel="self">` з абсолютним URL |

Перевірка: **387 файлів, невалідних 0** (`ElementTree.parse` по кожному).

### Сівба: ваш опис довелося уточнити, і це не дрібниця

Спершу я зробив буквально як написано — сівба це «перший запуск скрипта». Тоді ж
і побачив дірку: **масовий прохід ще йде.** Кожен перший прогін модуля дає
`prev is None`, тобто після завершення сівби решта проходу — ще ~2 900 модулів —
залила б фід рівно тими записами, від яких сівба захищає.

Тому сівба триває, **поки в черзі щось є**, і закінчується лише на порожній черзі:

```
змін записано: 1106 (сівба: так, у черзі 2923) · у фідах: 0 · курсор: 1129
```

`у фідах: 0` — саме те, що має бути зараз. Фіди порожні й валідні; перший
справжній запис з'явиться після завершення проходу.

Механізм виявлення змін перевірив окремо: вставив штучний прогін `ok → fail`
для вже перевіреного модуля, скрипт записав
`state_old=verified, state_new=verified, status_old=ok, status_new=fail`.
Штучний прогін після перевірки **видалено з `runs`**, курсор переставлено,
залишків немає — перевірив.

### Автовиявлення

`<link rel="alternate" type="application/atom+xml">` у `<head>` усіх сторінок.
На сторінці модуля — фід його **найновішої** серії, на сторінці вендора — його
власний. Читалка підхоплює правильний фід сама.

### Сторінки вендорів — довелося додати

Фід по вендору ви назвали гачком, і я згоден. Але знайти його не було як:
вендор у нас був лише значенням фільтра. Тому `/v/<slug>/` — список модулів
вендора, посилання на його фід і на відфільтровану головну. **382 сторінки на
мову.** Без них вендорський фід існував би, і про нього ніхто б не дізнався.

### Дефект у Caddy, знайдений на живому

Матчер `path /feed/*.xml` **не ловить** `/feed/vendor/<slug>.xml` — у Caddy `*`
не переходить через `/`. Вендорські фіди віддавались як `text/xml`:

```
/feed.xml                    application/atom+xml; charset=utf-8
/feed/19.0.xml               application/atom+xml; charset=utf-8
/feed/vendor/tecnativa.xml   text/xml; charset=utf-8      ← було
```

Замінено на `/feed/*`. Зараз усі чотири перевірені віддають `application/atom+xml`.

`changes.py` стоїть `ExecStartPre` до `export.py`: інакше кожен фід відставав би
рівно на годину. Фіди в `sitemap.xml` не включені — перевірив, 0 згадок.

## 6. GitHub поза OCA — цифри, які ви просили

```
  topic:odoo                 2536
  topic:odoo-modules          121
  topic:odoo-addons           447
  topic:odoo-apps              62
  topic:odoo, не OCA         2445
  topic:odoo, >5 зірок        397
  topic:odoo, оновл. 2026    1006
```

**Це нижня межа, і суттєво.** `topic:` спрацьовує лише якщо власник сам
проставив тему; репозиторій з модулями Odoo без тем сюди не потрапляє. Точнішу
оцінку дав би пошук по коду (`filename:__manifest__.py`), але code search у
GitHub **вимагає автентифікації** навіть для читання — тобто впирається в те
саме, від чого ми відмовились у випадку Store. Без токена цієї цифри не буде.

Практичний висновок для рішення: реально розглядати варто **1 006 активних**
(оновлені у 2026) або **397 із >5 зірок**. Перше зіставне з усією OCA
(232 репозиторії), друге — приблизно вдвічі більше за OCA. Тобто це не
доповнення на полях, це подвоєння-упʼятеро обсягу роботи.

І ваше застереження про якість я б посилив: у OCA є рев'ю і спільна структура
гілок. У випадковому репозиторії немає ні того, ні іншого — навіть гілки можуть
називатися інакше, і `harvest` їх не побачить. Тому це не «те саме, але більше»,
а окремий конвеєр із власними правилами. **Рекомендую відкласти до після
24 вересня** і не чіпати до завершення історії з 20.0.
