# Маршрут для краулера є. Реклами не буде. І сайт віддавав три фантоми з кодом 200

Обидва файли оброблені разом: другий переставляє порядок першого, а не додає
новий напрям.

## 1. Дві поправки до діагнозу, перш ніж про зроблене

**`meta name="robots"` на сайті БУВ.** Перед правкою:

```
# grep -rho 'name="robots" content="[^"]*"' var/site/ | sort | uniq -c
   1910 name="robots" content="noindex"
```

Посторінковий `noindex` для тонких сторінок реалізований із самого початку і
описаний у докстрінгу `page()`. Чого не було — це `follow`, і це справедливе
зауваження: додав.

**`hreflang` на сторінках модулів і вендорів теж уже стояв** — `page()` додає
alternates **усім** сторінкам без винятку, тому окремої правки тут не потрібно
було. У sitemap він тепер теж є, по два `<url>` на сторінку з повним набором.

Це не спір про дрібниці: обидва пункти були в переліку робіт, і якби я взяв їх на
віру, витратив би час на вже зроблене замість на B2. **Сама теза B2 справедлива
повністю і була найдорожчою з усього файла.**

## 2. Головне: у карті не було ні однієї сторінки модуля

Було 6 записів. Стало:

```
sitemap: sitemap-pages.xml — 6 URL · sitemap-modules.xml — 7166 URL ·
         sitemap-repos.xml — 322 URL · sitemap-vendors.xml — 1006 URL · разом 8500
```

`sitemap.xml` тепер `sitemapindex`. Ріжу по 40 000 URL на файл при ліміті 50 000 —
у вересні додається пʼята серія, і перевищити ліміт саме тоді, коли карта
найпотрібніша, було б у стилі решти дефектів цього тижня.

**`lastmod` = дата останнього ПРОГОНУ модуля, не дата генерації.** Приклад:

```
<url><loc>https://allservices.one/m/account-analytic/account_analytic_account_tag/</loc>
<xhtml:link rel="alternate" hreflang="en" href="…"/>
<xhtml:link rel="alternate" hreflang="uk" href="…/uk/…"/>
<xhtml:link rel="alternate" hreflang="x-default" href="…"/>
<lastmod>2026-08-20</lastmod></url>
```

Інакше кожен щогодинний `export` кричав би краулеру «усі 7 000 сторінок
змінились», і повторний обхід приходив би тоді, коли не сталося нічого.

**Критерій входження в карту — той самий `has_status`, що й критерій `noindex` на
сторінці.** Це не збіг, а те, що `append` стоїть рівно там, де рахується
`has_status`: інакше карта обіцяла б те, що сторінка забороняє. Перевірено
машинно, а не на око:

```
перевірено URL: 8500
розбіжностей: 0        ← усі існують на диску, і жоден не має noindex
```

`noindex` → `noindex,follow` (1 754 сторінки, плоского не лишилось жодного).
Виключити сторінку з індексу і обрізати маршрут через неї — дві різні дії, і
друга нам не потрібна: тонкі сторінки це вузли, через які видно залежності й
сусідів по репозиторію.

**Другий маршрут, як ти просив, працює вже зараз:** `/r/<repo>/` перелічує **всі**
модулі репозиторію звичайними `<a href>` — перевірив на `storage`: 37 посилань
при 37 модулях у БД. Тепер сторінки репозиторіїв ще й у карті, тож шлях
`sitemap → /r/… → /m/…` замкнутий і не залежить від скриптів.

## 3. Дефект, знайдений по дорозі: сайт віддавав вилучені модулі з кодом 200

`export.py` **ніколи не видаляв файли** — тільки писав. Тому на сайті лежали 16
сторінок модулів і репозиторіїв, яких в індексі давно немає:

```
m/server-auth/readme                              ← фантом, вилучений 19.08
m/stock-logistics-transport/lessons               ← фантом
m/delivery-carrier/delivery_carrier_label_gls     ← фантом
m/interface-github/github_connector               ← репо скошене жнецем з OCA
m/interface-github/github_connector_odoo
m/infrastructure-dns/base_dns_infrastructure
r/interface-github, r/infrastructure-dns          + ті самі 8 в /uk/
```

`SELECT ... FROM modules WHERE ...` по всіх шести — **0 рядків**. Тобто Caddy
віддавав із кодом 200 сторінки для трьох модулів, які ми самі довели, що не
існують, і які `CLAUDE.md` прямо забороняє публікувати.

Знайшлися вони випадково: у них лишився старий `content="noindex"` **без**
`follow`, і саме ця розбіжність у виводі `grep` їх виказала. Без правки з §2 вони
б мовчали й далі.

Тепер прибираються, і очікуваний набір рахується **з даних**, а не з того, що
писалось цього разу. Запобіжник як у жнеця (`inbox/0004` R1): понад 2% сторінок
або понад 100 під видалення — **не видаляється нічого**, лише крик у лог. Порожній
чи поламаний зріз не має права знести опублікований сайт.

```
прибрано зайвих сторінок: 16 із 10198 (m/stock-logistics-transport/lessons, …)
# curl -sI https://allservices.one/m/server-auth/readme/ → HTTP/2 404
```

## 4. Зворотний зв'язок

Підвал **усіх** сторінок обох дерев і окремий розділ у методології:

```
Questions or a wrong result: open an issue or hello@allservices.one
Питання або хибний результат: issue на GitHub чи hello@allservices.one
```

На сторінці модуля з вердиктом — заповнене посилання:

```
issues/new?title=Wrong+result%3A+fs_file_demo+on+17.0
 &body=Module%3A+storage%2Ffs_file_demo%0ASeries%3A+17.0%0ARun+date%3A+…
 %0AVerdict%3A+fail%2Fpy_version_syntax%0APage%3A+…%0A%0AWhat+I+expected%3A
 &labels=wrong-result
```

Серія береться **найновіша з вердиктом** — та, яку людина бачить першою і про яку
сперечатиметься. Тіло англійською незалежно від мови сторінки: issue читають в
одному місці. Форми немає й не буде — це динамічний endpoint і спам на статичному
сайті; записано в `CLAUDE.md`.

Розділ у методології називає цифру, яка робить прохання не формальністю: з перших
пʼятнадцяти `fail` девʼять виявилися **нашими** помилками, і знайшлися лише тому,
що хтось відкрив лог.

**Одне попередження, і воно важливе.** Аліас `hello@` створює власник у ImprovMX, а
я адресу вже опублікував на ~10 200 сторінках. Перевірити доставку з сервера
неможливо: SMTP не налаштований, свій MTA піднімати заборонено. **Поки аліаса
немає, лист на `hello@` відбивається — тобто саме той `550`, який ця правка мала
закрити.** Прибрати чи замінити адресу — один рух:
`SITE_CONTACT=<адреса> python3 indexer/export.py`. Канал, який працює незалежно від
пошти, — GitHub Issues, і він у підвалі першим. Записав як відкрите питання №4 у
`STATE.md`.

## 6. Старі URL: 410 замість 404

Ти маєш рацію по суті, і `/contactus` в індексі Google робить це не гіпотетичним.
Але спершу поправка до C: **вимоги «301 на субдомен» у `CLAUDE.md` немає.** Там
записано протилежне, у двох місцях — розділ «Домен» («Старі URL: 410, а не 301»)
і «Чого не робити» («Не робити 301 на старі URL»). Рядок, на який ти посилаєшся,
прибрано 19.08 разом із закриттям блокера AAAA. Невиконаної вимоги тут не було.

Рішення однаково зафіксував у `STATE.md` окремим розділом, як ти просив: **старий
ресурс не живе ніде**, цілі для 301 не існує, `410` правильний.

Цікаве було не в `/contactus`. Я подивився **власний лог** Caddy замість
здогадування, і найбільший 404 — не той, про який ти писав:
