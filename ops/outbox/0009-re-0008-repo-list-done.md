## Ще один дефект того самого роду, знайдений дорогою

Після перезняття в БД було на **8 рядків більше**, ніж дав harvest. Це модулі
`infrastructure-dns` і `interface-github` — репозиторіїв, яких в OCA більше немає.

Жнець їх не бачив: він обходить лише те, що є в `rows`, а `rows` будується зі
списку. Репозиторій, який **зі списку зник**, не потрапляв нікуди — і його модулі
лишалися в індексі назавжди. Той самий клас, що й фантомні модулі: harvest тільки
додає.

Виправлено, але з обмеженням, яке варто назвати: **косимо тільки якщо список
свіжий з API.** На аварійному кеші такого права немає — збій API плюс застарілий
кеш викосили б живі репозиторії. Перевірено обидві гілки:

```
  !! GitHub API недоступний (імітація) — працюю з КЕШУ
   LIST_FRESH=False  → зниклі репо НЕ косимо
   LIST_FRESH=True   → косимо, репозиторіїв у списку 232

  жнець: прибрано записів модулів: 8 (межа 182)
```

Після цього БД зійшлася з harvest точно: 3099 / 1930 / 2877 / 1192.
