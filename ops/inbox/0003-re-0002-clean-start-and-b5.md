### `series_snapshots` — краще не видаляти, а версіонувати метод

Видалення знищує докази. Два зрізи (18.08 і 19.08) дали спостереження «+5 модулів на
19.0 за добу», і воно варте того, щоб лишитися. Проблема не в самих рядках, а в тому,
що після B4 їх нельзя класти в один ряд із новими для розрахунку нахилу.

Тому додайте колонку методу — і проблема закривається назавжди, а не лише зараз
(наступна зміна методології обовʼязково буде):

```sql
ALTER TABLE series_snapshots ADD COLUMN method text NOT NULL DEFAULT 'v2';
UPDATE series_snapshots SET method = 'v1';   -- усе, що зняте до B4
```
`v1` — теки верхнього рівня без перевірки манифеста. `v2` — тека з `__manifest__.py`
на першому рівні. Графік темпу й будь-які похідні цифри вважати **тільки в межах
одного методу**: `WHERE method = 'v2'`. У `schema.sql` — `DEFAULT 'v2'`.

## B5 — нове, і важливіше, ніж виглядає: harvest ніколи не видаляє

`harvest.py` робить `ON CONFLICT … DO UPDATE` і не видаляє нічого. Наслідки:

1. Фантом `stock-logistics-transport/lessons` після B4 **не зникне сам** — він просто
   перестане оновлюватись.
2. Гірше: коли модуль **приберуть** з гілки в апстрімі, наш індекс показуватиме його
   вічно. Для індексу, який заявляє «фактичний стан», це прямий дефект.

Колонка `seen_at` для цього вже є. Правило: після **успішного** обходу видаляти рядки,
не побачені в цьому прогоні, — але **тільки для тих пар (репозиторій, серія), які
цього разу обійшлися без помилки**. Інакше недоступний на хвилину GitHub зітре
половину індексу.

```python
# у harvest: збирати successfully_seen = {(repo, series), …} лише для гілок,
# де clone/ls-tree повернули rc=0
for repo, series in successfully_seen:
    cur.execute("""DELETE FROM modules
                   WHERE repo=%s AND series=%s AND seen_at < %s""",
                (repo, series, run_started_at))
```
`runs` при цьому каскадно приберуться — і це правильно: у модуля, якого більше немає
на гілці, статусу бути не повинно. У `ops/outbox` напишіть, скільки рядків видалилося
першим таким прогоном: очікую рівно 1 (`lessons`).
