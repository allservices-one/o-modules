# 0024 · SSH закрито. Ребут — зараз, поки черга порожня

## A. Вхід по паролю закритий власником 21.08.2026

Зроблено вручну, у двох паралельних сесіях, із перевіркою з третього
з'єднання — тобто без ризику замкнутися зовні.

`/etc/ssh/sshd_config.d/99-hardening.conf`:

```
PasswordAuthentication no
KbdInteractiveAuthentication no
PermitRootLogin prohibit-password
```

Діюча конфігурація після `systemctl reload ssh`:

```
permitrootlogin without-password
passwordauthentication no
kbdinteractiveauthentication no
```

`without-password` — це та сама настройка, що `prohibit-password`, старішою
назвою; вона вже стояла до рядка `Include`, а діє перше входження. Блоків
`Match` немає (перевірено `grep -rn '^Match'`).

Контрольний тест із Mac:

```
$ ssh -o PubkeyAuthentication=no -o PreferredAuthentications=password root@…
root@…: Permission denied (publickey).
```

Пароль **не запитано взагалі** — сервер пропонує лише `publickey`. Резервна
копія: `/etc/ssh/sshd_config.bak.2026-08-21`.

**Прошу відзначити це в `ops/STATE.md`** — пункт висів із першого дня і його
пора прибрати зі списку відкритих.

## B. Ребут: вікно відкрите **зараз** і скоро закриється

Банер входу: `*** System restart required ***`, 11 доступних оновлень, ядро
оновлене але не завантажене.

**Робити поки `queue` нульова.** Це не косметика. Якщо ребут застане прогони в
роботі:

- задачі залишаться у стані `running` із виставленим `locked_by` і `locked_at`, і
  чекатимуть reaper замість того, щоб виконатися;
- на диску лишаться недобиті одноразові БД прогонів і, можливо, контейнери;
- у `runs` не буде ні результату, ні ознаки, що прогін обірвався — тобто тиха
  втрата, той самий клас дефекту, який ми ловимо весь тиждень.

Зараз черга нульова. Щойно почнеться 16.0 — це вікно закриється на добу.

### Порядок

```
apt update && apt upgrade -y
reboot
```

### Чек-лист після ребуту — з доказами в outbox, не «все піднялося»

1. `docker ps` — **обидва** контейнери: `modidx-pg`, `modidx-caddy`, обидва healthy.
2. Шаблонні БД на місці і досі шаблонні:
   `SELECT datname, datistemplate FROM pg_database WHERE datname LIKE 'tmpl_%';`
   Усі мусять мати `datistemplate = t`.
3. `systemctl status 'modidx-*'` — таймери `harvest`, `export`, `maint`, вартовий
   гілки з 0022, і воркери `runner@1`, `@2`. Що було enabled — мусить бути enabled.
4. `swapon --show` — 4 ГБ на місці. Після ребуту swap-файл інколи не
   підключається, якщо його немає у `fstab`.
5. `curl -sI https://allservices.one` — 200 і живий сертификат.
6. `status.json` перегенерувався у наступну годину, `generated_at` свіжий.
7. **Задач у стані `running` бути не має:**
   `SELECT state, count(*) FROM jobs GROUP BY 1;`
   Якщо є — це залишок, а не робота: звільнити й описати, чому вийшло.
8. `df -h /` і `free -m` — порівняти з тим, що було до ребуту.

Якщо якийсь юніт не піднявся сам — це знахідка, а не дрібниця: 24 вересня
перезавантаження може статися не за нашим планом.
