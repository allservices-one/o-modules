# Протокол обміну через git

Тут спілкуються дві сторони, які не бачать одна одну:

- **review** — сесія в Cowork. Має доступ лише до 80/443: читає цей репозиторій
  через `git clone` і живий сайт. SSH до сервера **не має і не матиме**.
- **server** — сесія Claude Code в `/srv/modidx`. Має повний доступ до сервера,
  пушить у цей репозиторій через deploy key.

Власник — не транспорт для логів. Він лише запускає `git push` / `git pull`
і каже кожній стороні «оновись». Усе інше сторони пишуть одна одній самі.

## Головне правило: один писар на шлях

Конфліктів не буває, бо ніхто не редагує чужі файли.

| Шлях | Хто пише | Хто читає |
|---|---|---|
| `ops/inbox/NNNN-*.md` | **тільки review** | server |
| `ops/outbox/NNNN-*.md` | **тільки server** | review |
| `ops/STATE.md` | **тільки server** | обидва |
| код, `CLAUDE.md`, `STEPS.md` | переважно server | обидва |

Файли **тільки створюються**, ніколи не редагуються після пушу. Номер не
перевикористовується: наступний = максимальний **в обох теках разом** + 1.

Нумерація **єдина наскрізна** для `inbox` і `outbox`. Спершу вона була окрема на
теку, і це дало `inbox/0003` поруч із `outbox/0003` — у розмові «0003» стало
двозначним. Один рахунок на обидві теки прибирає це назавжди.

**Номер вважається зайнятим лише після push.** Обидві сторони пишуть паралельно,
тому максимум, порахований до чужого push, застаріває — так з'явилися
`inbox/0011` і `outbox/0011` одночасно. Порядок: `git pull --rebase` →
порахувати максимум **в обох теках** → писати. Якщо push відкинуто —
**перенумерувати перед повторним**, а не `--force`. На вже опубліковані
дублікати посилатися з префіксом напрямку: `inbox/0011`, `outbox/0011`.

## Формат

Ім'я: `0007-re-0003-runner-fix.md` — свій номер, на що відповідає, слаг.

Кожен файл починається шапкою:

```
---
id: 0007
re: 0003
from: server
date: 2026-08-19T14:22:00Z
status: done | partial | blocked | question
---
```

Далі — по суті. Для `outbox` обов'язково:

1. **Що зроблено** — коротко, по пунктах.
2. **Докази** — справжній вивід команд, обрізаний, але не переказаний.
   Переказ логу замість логу робить весь цей канал безглуздим.
3. **Що не зроблено і чому.**
4. **Питання, які блокують**, якщо є.

## Обов'язковий цикл

**server**, на початку кожної роботи:
```bash
cd /srv/modidx && git pull --rebase
ls ops/inbox/ | tail -5        # чи є нові вхідні
```
після кожного змістовного кроку:
```bash
bash bin/ops-check.sh          # НЕ пропускати: репозиторій публічний
git add -A && git commit -m "ops: 0007 …" && git push
```
і оновлює `ops/STATE.md`.

**review** пише у `ops/inbox/`, власник пушить з Mac.

## Репозиторій публічний і суто технічний

Тут лежить те, як індекс влаштований і чому саме так. **Не лежить** і не має
лежати: графік виходу, канали просування, монетизація, цінник, точка go/no-go,
чернетки листів до третіх сторін. Це вилучено 19.08.2026 і живе у приватному
просторі власника.

`ops/letters/` і `_to_delete/` — у `.gitignore` назавжди.

На технічні рішення це не впливає: дедлайн 24.09.2026, обмеження сервера
(4 vCPU / 8 GB, два воркери) і всі заборони в `CLAUDE.md` лишаються. Якщо
здається, що для задачі потрібен комерційний контекст — **запитати власника, а не
здогадуватись і не відтворювати його тут**.

### Виняток із правила «файли лише створюються»

Опубліковані файли не редагуються — крім **одного** випадку: вилучення
комерційного або чутливого вмісту. Саме так 19.08.2026 були відредаговані
`inbox/0012` і `0013` уже після push. Це правильний виняток: публічність
важить більше за акуратність історії. Будь-яка інша правка опублікованого —
новий файл, а не редагування.

Наслідок, який варто пам'ятати: посилання на вилучене лишаються в старіших
файлах і стають мертвими (`outbox/0014` посилається на `ops/letters/`).
Не виправляти заднім числом — згадати в наступному звіті.

## Секрети: репозиторій ПУБЛІЧНИЙ

Пароль Postgres у `ops/` потрапити не має.

Раніше `runner.py` передавав його прямо в командному рядку `docker run`, і він
світився в `ps`, `systemctl status` та journald — тобто в будь-якому виводі, який
природно хочеться скопіювати сюди. Виправлено 19.08.2026: `-e ІМʼЯ` без значення,
docker бере змінну з оточення (`runner.py`, `mktemplate.sh`, `maint.sh`).
Джерело витоку прибране, але перевірка лишається обовʼязковою — `.env` нікуди не
подівся, а вивід `psql` чи бекапу може містити що завгодно.

Перед кожним комітом — `bash bin/ops-check.sh`. Він шукає у файлах, що йдуть
у коміт, пароль з `.env`, `PGPASSWORD`, `BEGIN … PRIVATE KEY`, `ghp_`/`github_pat_`
і зовнішні IP. Замінювати на `[REDACTED]`, не видаляти рядок цілком —
структура логу має лишатися читабельною.

Ніколи не комітити: `.env`, `var/`, `pf.txt`, вміст архіву старого проєкту.

## Чого не робити

- Не редагувати файли іншої сторони — навіть «щоб виправити дрібницю».
- Не переписувати історію (`push --force`) — друга сторона працює з тим,
  що вже прочитала.
- Не переказувати логи. Вивід команди дослівно або нічого.
- Не чекати від власника пояснень, що сталося раніше: стан читається з
  `git log`, `ops/STATE.md`, БД і живого сайту.
