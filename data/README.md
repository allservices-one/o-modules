# Датасет

Два різні класи файлів, які легко переплутати.

## Щоденні, оновлює `bin/maint.sh` (таймер `modidx-maint.timer`, 04:40)

| Файл | Що це |
|---|---|
| `series_snapshots.csv` | **історія зрізів цілком**: `taken_at, series, repos, modules, installs_ok, method` — по рядку на добу × серію |
| `modules.csv` | поточний стан: модуль × серія, наявність, статус прогону, причина, версія |
| `blocking.csv` | рейтинг блокувальників міграції: модуль без гілки наступної серії, скільком він потрібен, скільком він **єдина** відсутня залежність |

`series_snapshots.csv` — незамінна частина. Код перепише будь-хто, прогони
детерміновані й повторюються, а рядок «станом на 19.08.2026 на 19.0 було 1 192
модулі» заднім числом не добудовується ні з чого. Тому таблиця вигружається
**цілком**, а не поточним зрізом, і саме тут вона має offsite-копію.

`method` розділяє методики підрахунку (`v1` — будь-яка тека верхнього рівня, до
19.08.2026; `v2` — тека з `__manifest__.py`). **Нахил і будь-які похідні цифри
рахувати тільки в межах одного методу.**

## Еталон 18.08.2026, не оновлюється

| Файл | Що це |
|---|---|
| `oca_modules.csv` | список модуль × серія станом на 18.08.2026 |
| `oca_snapshot.csv` | по репозиторію: наявність гілки, кількість модулів, дата останнього коміту |

Це замір, з яким звіряються всі наступні (`CLAUDE.md`, «Тверді факти»). Перезаписувати
його свіжими даними не можна — тоді нічого буде звіряти.

`oca_repos.txt` — аварійний фолбек списку репозиторіїв OCA, коли GitHub API
недоступний. Не датасет, не видаляти.

`indexnow.key` — ключ IndexNow (`indexer/indexnow.py`). **Публічний за
призначенням**: протокол вимагає, щоб той самий рядок віддавався за адресою
`https://allservices.one/<ключ>.txt` — це і є доказ володіння доменом. Тому він у
git, а не в `.env`. Найгірше, що дає чужий ключ, — змусити краулер обійти наші ж
сторінки. Не переставляти: новий ключ треба заново опублікувати файлом.
